## 3. Killer-test narrative (full-pipeline.spec.ts)

`data/sales_2026_09_09.csv` was copied into `data/incoming/` and submitted through the real Pipeline page's "Run one file" control (radio → filtered selectbox → "Run" button - a real Streamlit UI interaction, not an API call). The blocking `run_pipeline_subprocess()` call was awaited via its actual completion signal (the "Running..." spinner text leaving the DOM), then the resulting `pipeline_runs` row was read directly from Postgres as ground truth.

**Real finding**: this exact file had already been successfully ingested in an earlier session (Postgres's named Docker volume persists across container recreation) - `pipeline_runs` run_id 191, `SUCCESS`. Every submission in this session's runs therefore correctly returned `SKIPPED_DUPLICATE` via SHA-256 duplicate detection - itself a real, verified behavior, not a workaround. `file_registry` was confirmed to hold exactly one row for the file's hash after each resubmission.

Downstream, against the original run's data:
- **Data Quality** page showed real per-dimension scores (`Completeness`, `Validity`, etc.) for the correct `run_id`, selected via the page's own run-picker dropdown.
- **Planted anomaly** (`West → Electronics → Laptop`, `docs/anomaly-ground-truth.md`): cross-checked with a direct SQL aggregate against `fact_sales` for the documented anomaly window (2026-08-01..2026-09-08) - confirmed non-zero order/revenue rows for that exact slice, independent of the UI.
- **Root Cause, Business Impact, Forecast, Recommendations** pages all rendered without a server-side traceback.
- **AI Analyst**: asked "Why did revenue decrease?" (the same question `scripts/run_final_demo.py` uses) via the real quick-question button; the response showed `Engine: template` (matching the no-LLM-configured environment) with an `Intent/Confidence` line and a Summary section - real evidence assembly (`src.ai_evidence`), not a fabricated answer.
- **Reports**: the original run's `stage_metrics.report` Excel/PDF paths were checked directly against disk; where still present, validated as real OOXML (`adm-zip`, 12 named sheets from `src/reporting.py::SHEET_NAMES`) and real PDF (`%PDF-` magic bytes).
- **Logs** page showed the just-created run.
- **Rejected records**: zero for the original run, matching the demo file's documented "clean, no injected defects" generation.
- Zero unexpected console errors throughout.

## 5. Security results

`src/nl_to_sql.py`'s `ask()` has no template fallback for SQL generation - without a configured LLM, every question (malicious or benign) correctly returns the honest "AI query generation is unavailable" message before `validate_sql()` (the actual injection defense) runs. Verified: no fabricated SQL or results ever appear. `validate_sql()`'s own blocking logic (banned keywords, table whitelist, single-statement rule) is separately, directly unit-tested in `tests/test_phase29_nl_to_sql.py` - not re-verified through the browser in this session for lack of an API key. Full detail in `docs/CHROME_E2E_AUDIT.md` §4.

Prompt-injection probe (§5 of the audit): three adversarial questions all produced the same honest template fallback response; no credential-shaped text leaked.

## 6. Accessibility results

Zero serious/critical violations in InsightForge's own page content on Overview, Pipeline, Anomalies, and AI Analyst, after correctly excluding Streamlit's own framework chrome (`stHeader`, `stSidebarCollapsedControl`, `stSidebar` - real critical violations, but in vendored `streamlit` package markup, not this project's code). One real, sitewide finding recorded (not hard-failed): Streamlit's default `st.caption()` text color fails WCAG AA contrast (3.68:1 vs 4.5:1 required) - a framework theme default used throughout the app. Full detail in `docs/CHROME_E2E_AUDIT.md` §6.

## 7a. Responsive & anti-hardcoding results

`responsive.spec.ts`: 9/9 checks pass (3 pages × 3 resolutions: 1366×768, 1536×864, 1280×720) - no horizontal overflow beyond a 5px tolerance, sidebar nav or its collapse toggle remains reachable at every size.

`data-change.spec.ts`: real day-to-day revenue variation confirmed across the 5 most recent `daily_kpis` rows (not a constant/hardcoded value), and the Overview page's revenue tile confirmed to match the database's exact value for the latest date. See `docs/CHROME_E2E_AUDIT.md` §6a for the real finding that reshaped this test - the platform enforces a hard `2026-09-09` "narrative present" date ceiling, confirmed by two real rejected-ingestion attempts, so a "new future day" ingestion proof isn't possible without violating the app's own correct validation.

## 9. Known limitations

- Power BI: no browser target exists by design; not tested (see audit §7).
- Live email delivery: no SMTP catcher stood up; only the documented graceful no-send path verified (see audit §7).
- Real, LLM-backed NL-to-SQL injection blocking: requires a configured `GEMINI_API_KEY`, unavailable in this session; `validate_sql()` is unit-tested directly instead.
- The full literal 73-section checklist from the original prompt was scoped down with explicit user approval; see audit §7 for exactly what's excluded.
- `resilience.spec.ts`'s two checks resubmit an already-ingested historical file (`sales_2026_09_08.csv`), so they legitimately exercise the `SKIPPED_DUPLICATE` path rather than a fresh multi-second pipeline run - this is real, correct behavior for the current database state, not a weakened test.
- Running this suite repeatedly over a long session accumulates stray `chrome.exe` processes on this host that are not always cleaned up by Playwright/Chrome itself; two runs failed for this reason during development (browser launch timeout, then a ~29-minute hang) until stray processes were killed. Anyone re-running this suite many times in one sitting should watch for this.
- `data-change.spec.ts` could not prove the strongest form of its intended anti-hardcoding claim (ingesting a truly novel future day) because the platform's own data contract correctly rejects any date after 2026-09-09 - this is documented as a real platform characteristic, not downplayed.
