# Frontend Audit

## 1. Scope & method

A prompt requesting a full frontend rebuild (Streamlit + Power BI) assumed the
frontend was largely unbuilt. Before writing any code, the existing
`streamlit_app/` (11 pages), `dashboard/` (Power BI DAX/M assets), and the
`src/` analytics modules those pages call were read in full. "Gap" here means:
a feature with a complete, already-tested `src/` implementation that isn't yet
surfaced anywhere in the UI - not a missing backend capability (there were
none) and not a cosmetic preference.

## 2. Findings

| Gap | Backing `src/` module | State before | Fix |
|---|---|---|---|
| No Recommendations page | `src.recommendations.generate_recommendations` | Only top-5 shown on Overview | Added `pages/11_Recommendations.py` (full list, severity/band filter) |
| No Reports page | `src.reporting.generate_reports` (paths already in `pipeline_runs.stage_metrics.report`) | Report paths generated per run but never surfaced | Added `pages/12_Reports.py`, downloads gated on the file actually existing and being non-empty |
| No Alerts page | `src.alerts.build_alert`/`route_for_severity` | Alert routing computed only inside the orchestrator (which also sends real email) | Added `pages/13_Alerts.py`, calling only the pure `build_alert()` - never `dispatch_alerts()`/`send_alert_email()` |
| Overview missing KPI tiles | `daily_kpis` view already has `aov, margin_pct, customers, avg_discount_pct, avg_shipping_days` | Only revenue/profit/orders/return_rate shown, no trend | Added the 5 missing tiles + day-over-day `delta` on every tile, reusing the already-fetched `compare_period(db, "day")` call (no new query) |
| No data-freshness indicator | `pipeline_runs`, `daily_kpis` | Not shown anywhere on Overview | Added last-run + data-date-range caption |
| Business Impact has no filter | `src.impact_analysis.assess_business_impact_series` returns the full series already in memory | Whole history always shown | Added an in-memory date-range filter (no extra query) |

## 3. Filter audit (per existing page)

## 4. Explicitly out of scope (user decision)

- **Global/shared sidebar filter architecture** (session_state propagated into every page's queries) - rejected in favor of keeping the existing per-page filter pattern (`st.selectbox`/`st.date_input` inline, matching Root Cause/Forecast/Anomalies).
- **Plotly/Altair** - no new charting dependency; all new/changed charts use the same native `st.line_chart`/`st.bar_chart`/`st.metric` already used throughout.
- **Rewriting working pages** - Pipeline, Data Quality, Anomalies, Root Cause, Forecast, Customers, Products, AI Analyst, Logs were read in full and left untouched; they already query real backend data, have working loading/error/empty states, and no hardcoded values were found in any of them.
- **Power BI** - `dashboard/*.dax`/`*.pq` and `docs/powerbi-data-model.md`/`docs/powerbi-pages.md` already document a complete 7-page model built from real Postgres views. No `.pbix` file is ever generated by design (it's a GUI-only binary artifact; fabricating one would violate this project's "never fake functionality" rule) - this is documented project policy, not a gap, and was left untouched.
